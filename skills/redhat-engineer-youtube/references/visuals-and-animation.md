# Scenes and animation

## Building the shotlist

Take `03_audio/timings.json` and the visual notes from `02_script/shotlist.json` and produce a final shotlist where every second of narration is covered by a scene.

- One scene per **6–10 seconds** of narration. A 6-minute video is typically **35–55 scenes**.
- Every scene gets motion — see Animation below. Never hold a flat static image longer than 10 seconds without a cut. Static-image drift is the #1 killer of retention in AI-made explainers.
- Vary shot type deliberately: wide establishing → mid explanatory → close emphasis → diagram → scale comparison → real photo → back to character. Two consecutive shots of the same type should feel like a choice, not an accident.
- Match cut on meaning: when the narration says "and then it got smaller", the cut *is* the size change.

This is the **final** shotlist, and it lives in `05_scenes/shotlist.json` — a different file from the draft `02_script/shotlist.json` written in stage 2 (one-line visual notes jotted alongside the script, before `timings.json` exists). This final version is authoritative: it's keyed to real beat timing, and `scripts/assemble_episode.py` reads its `motion` field directly to pick each scene's zoom direction (see Animation below). Format:

```json
[
  { "scene": 1, "start": 0.0, "end": 4.8, "type": "close",
    "description": "Host holds up a tiny transistor between two fingers, red highlight on the object",
    "characters": ["host"], "motion": "slow push in", "onscreen_text": null }
]
```

Set `motion` explicitly per scene from context — `"slow push in"` for emphasis, a reveal, or a close shot; `"slow push out"` for an establishing or scale shot. This drives the zoom direction via `assemble_episode.py`'s `pick_zoom_direction`; if left unset it alternates in/out automatically by beat number, but a deliberate choice reads better than a coin flip.

`onscreen_text` stays `null` for almost every scene. This is a story channel, not an educational one — a frame full of labels reads as a lecture slide. Leave it `null` unless a single key term, number, or date genuinely needs the emphasis, and never more than 2–3 words when it's used.

## Generating scene images

Scene images are generated by FLUX.2 [klein] (9B by default) on Cloudflare
Workers AI against the channel's own brand character. Run from
`RedHatEngineer/`:

```
python3 scripts/generate_scenes.py <slug>
```

For every beat whose shotlist `type` isn't `"real_photo"`, this:
1. Builds a prompt from the shotlist description (`scripts/scenes/prompt_builder.py`):
   the locked style suffix (hand-drawn marker stickman on a white whiteboard, see character-bible.md),
   followed by `{description}`, at `1024x576`.
2. Writes/updates `05_scenes/prompt_plan.json` (one entry per beat, inspectable before spending any free-tier quota).
3. Calls the Cloudflare Workers AI REST API (`scripts/scenes/cloudflare_generator.py`) once per beat, sending the prompt, size, seed and the reference image (`brand/host-reference-clean.jpeg`), and writes `05_scenes/scene_XXXX.png`. Credentials come from `.env` / the environment (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; optional `CLOUDFLARE_IMAGE_MODEL`, default `flux-2-klein-9b`). Transient errors (429/5xx) are retried with backoff; bad credentials or a spent free daily quota (10,000 neurons) stop the batch, and a rerun only generates the beats that are still missing.

| Flag | Effect |
|---|---|
| `--dry-run` | Write/print the prompt plan, make no Cloudflare calls |
| `--beats 1,3,5-7` | Only (re)generate specific beat numbers |
| `--seed N` | Force this seed for the single beat selected by `--beats` |

**Known limitation:** FLUX.2 klein reliably composes at most 2
distinct characters in one shot — write beats with 3+ characters as
shot/reverse-shot pairs instead (see `character-bible.md`). Review
`05_scenes/*.png` before running `assemble_episode.py`; fix a bad beat
with `--beats N --seed <new>`, not by tweaking the shared params.

A beat needs a hand-placed image only when its shotlist `type` is
`"real_photo"` (a real photo, historical document, chip die-shot —
anything the generator shouldn't touch): place it at
`episodes/<slug>/05_scenes/scene_XXXX.png` before running
`assemble_episode.py`, which will refuse to proceed if that file is
missing. Licensing rules in `compliance-and-safety.md`.

## Animation

FLUX.2-klein-4B only produces static images — there is no live
per-frame character animation in this pipeline. Motion comes from ffmpeg
`zoompan` in `assemble_episode.py`: every scene gets a Ken Burns push
in/out, ~6% zoom ramped over the scene's full duration, direction read
from the shotlist's `motion` field (`"slow push in"` / `"slow push
out"`), falling back to alternating in/out by beat number if unset. A
deliberate choice per scene reads better than a coin flip — set
`motion` explicitly when building the shotlist.

**Specs:** 1920×1080, 24 fps. There is no separate `06_animation/`
stage — motion happens inline inside `assemble_episode.py`'s ffmpeg
call.

**Never:** morph transitions between characters, fast whip-pans, shaky
cam, rapid strobing, or more than one motion idea per scene.

## Recurring visual devices (build these once, reuse forever)

- **The timeline strip** — a horizontal line with year markers that returns whenever the story jumps in time. Viewers learn to read it instantly.
- **The scale ruler** — host beside object at true relative size.
- **The before/after split** — the world without the invention on the left, with it on the right.
- **The chain diagram** — invention A enables B enables C, with red highlighting the current node.
- **The "meanwhile" card** — a simple title card for parallel storylines.

Consistent devices are the visual equivalent of a catchphrase. They make a 60-scene video feel authored rather than assembled.
